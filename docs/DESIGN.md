# 视觉与动效方案

## 设计方向

面向来玩小游戏的人，做圆润、有体积感的游戏陈列架。趣味主要来自造型、动作和游戏本身，文案只解释必要操作与状态。不要拟人化补充，也不要刻意把说明截成口号；失败结果页按用户认可的版本保留。

设计参数：`DESIGN_VARIANCE: 6`、`MOTION_INTENSITY: 8`、`VISUAL_DENSITY: 3`。允许卡片构图活泼，导航与操作保持明确；开场和反馈有弹性，稳定页面保持安静。

采用定制视觉语言，不冒充 Material、Apple 等官方设计系统。实现位于 src/，已接入首页和游戏页面。

## 信息与组件层级

```text
站点外壳
├── 开场 / 共享标题
├── 顶部导航 / 全站声音设置
├── 游戏列表
│   └── 游戏卡片：实景或规则引擎渲染的预览、名字、进入按钮
└── 游戏容器
    ├── 返回、游戏名称、必要设置
    ├── 关卡 / 当前苹果数
    ├── 游戏棋盘
    ├── 操作、重开、规则说明
    └── 死亡 / 通关结果
```

基础圆角、按钮、浮层、排版、动画参数使用共享 token。苹果、蛇和地块属于游戏视觉，不反过来决定站点公共组件的 API。

## 色彩与体积

- 站点用统一中性色背景，主按钮使用浅绿色。按用户后续要求，标题字母使用五色，标签、分数与方向按钮使用对应色彩。
- 苹果红、蛇身色、地块色承担游戏对象区分，可独立于站点强调色。
- 不同层级用表面明度、边缘高光、接触阴影和间距区分。
- bloom 只用于少量高光与出口等需要强调的对象，避免大面积模糊影响清晰度。
- 深浅主题使用语义 token 并跟随系统，保持同一套形状与层级。
- 游戏棋盘优先保证格子、碰撞边界和支撑关系容易辨认。

## 开场节奏

建议总时长约 2.5 秒，实际以浏览器观感调整。

| 阶段 | 建议节奏 | 目的 |
| --- | --- | --- |
| 字母冒泡 | 字母间错开约 25ms；每个弹簧衰减约 350ms | 逐字建立标题，轻微挤压再回弹 |
| 标题短暂停留 | 约 250ms | 给完整标题一次阅读机会 |
| 标题收进左上角 | 约 600ms，较沉的弹簧 | 通过共享元素保持位置连续 |
| 卡片出现 | 错开约 70ms，轻弹入场 | 把注意力交给游戏入口 |

开场可跳过；减少动态效果时直接呈现正常布局。返回列表不重播完整开场。是否每次刷新都播放可在实施时用当页内存处理，不写入游戏进度存储。

## 交互反馈

- 按钮按下：短暂压缩，松开恢复，先响应输入再完成回弹。
- 卡片：指向时微抬，点击后连续过渡进入游戏。不要为了效果迫使用户等动画。
- 吃苹果：苹果消失、尾部增长、计数更新形成一次明确事件；视觉表现不改变逻辑先后。
- 重力：下落加速，落地短暂挤压回弹。不能因为装饰弹性改变实际落点。
- 死亡：保留足够局面信息，清楚提供重开。
- 通关：展示本局结果与实际可用的后续操作，不暗示已经保存成绩。

## 可用性

- 键盘焦点清晰，按钮有明确名称。
- 页面滚动和游戏方向输入分别管理，游戏外不拦截方向键。
- 手机触控按钮至少 44 CSS px。
- 关闭声音或空 WAV 不影响游戏进行；浏览器未解锁音频前不主动播放。
- 动画主要用 transform 和 opacity。少量必要的共享布局测量与游戏状态更新各自隔离。
- reduced motion 关闭弹跳、摇晃和装饰循环，保留即时状态变化。

## 2026-11-02 本轮修订

- 保留原有圆润、多色方向；标题蓝色重点、薄表面高光、卡片底边和按钮按压力度区分层次。手机顶部语言选择保持 44 px 触控高度，320 px 下不产生横向滚动。
- 首次语言弹窗先于开场，主界面中英文互斥显示；标题冒泡和共享元素连续过渡保留。玩法说明使用独立全屏遮罩，不被小棋盘高度裁切。
- 片尾两列始终等宽，姓名固定顶部，滚动时保留对齐；正常 64 px/s、按住回车/屏幕按钮 512 px/s。减少动态效果时手动滚动，按住加速仍可主动滚动。
- 六类透明 PNG 贴图由内置 image_gen 生成并接入，素材在 public/Art/gravity-snake/，提示词见 docs/art-prompts.json。压缩尺寸后共约 0.81 MB，原始生成文件保留在生成目录。
- 追尾怪物视觉宽约 6 格；倒计时后段逐渐靠近，咬尾有 380 ms 扑动和轻微画面反馈。倒计时与画面左缘颜色提示危险，不增加虚构碰撞范围。
- 追逐关镜头同时跟随横向和纵向位置，减少上方空场景；手机更容易同时看到路线与操作按钮。蛇移动、刚体下落、落地压缩与吃苹果得分反馈分别处理，规则仍由纯引擎决定。

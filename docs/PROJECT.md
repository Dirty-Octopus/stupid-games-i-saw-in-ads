# 项目需求

建立日期：2026-11-01。更新日期：2026-11-02。状态：首版本地实现与核验，等待正式音效交接。

## 定位

在网页上复刻用户在视频、广告或不同平台上看到的小游戏。用户提出大概机制，开发者先澄清影响结果的歧义，再完成实现、验证和音效接入。

英文站名：**stupid games i saw in ads**。

中文站名：**那些我在广告里看到的傻X小游戏**。

## 首版范围

- 站点开场与首页游戏卡片。
- 第一个游戏：重力贪吃蛇。
- 桌面及手机可用的布局与交互，方向键 / WASD 与屏幕方向按钮。
- 弹性动效、圆润造型、清晰视觉层次与克制体积效果。
- 游戏事件对应的 WAV 占位文件及替换说明。
- 前后端边界和可替换的数据访问接口。
- 本地验证与交付。

不在当前阶段实现：后端服务、账号、分数持久化、进度持久化、排行榜及线上部署。运行中的分数与当前局面可以在内存中存在。

## 首页体验

1. 首次打开网站，先在页面内选择语言；已选择时读取语言偏好。随后中心出现英文标题。
2. 字母逐个像泡泡一样弹出。
3. 使用同一个视觉元素连续移动并缩小到左上角，不以两个标题交叉淡入假装共享元素。
4. 中心展示游戏卡片。第一版只有一个真实游戏，不添加虚构占位游戏。
5. 选择卡片进入对应游戏。离开游戏可回到列表。

## 固定工作流

用户给机制/参考 → 澄清关键歧义 → 更新游戏需求 → 本地实现与验证 → 列出 WAV 占位和用途 → 用户替换音效 → 接入核验与确认 → 按用户指令推送 → 全面确认后部署 Pages。

每次回复以实际状态为准，不能把规划、待确认建议或未执行检查写成已经完成。

## 交付验收

### 站点

- 标题内容及中文译名正确。
- 冒泡开场和标题移动连续，不卡住后续操作。
- 游戏入口清晰，按钮有按压和焦点反馈。
- 手机无横向溢出，触控目标足够大。
- 支持 `prefers-reduced-motion`。
- 可见文案简短，没有宣传段落、虚构游戏或虚构成绩。

### 游戏

- 按确认的规则验证初始长度、移动、增长、支撑、下落、死亡和通关。
- 以实际解法或搜索结果证明每个关卡可解，不只凭视觉判断。
- 输入不会在动画期间造成状态重入；重开和退出后没有残留输入、计时器或音效。
- 苹果计数准确，结算按最终确认的规则计算。
- 音效事件与动作同步；空音效不导致播放报错。

### 架构与发布

- 当前无分数/进度存储和后端请求。
- 规则不依赖显示与网络层，未来可接后端适配器。
- Pages 仓库子路径下资源可加载。
- 没有未经用户要求的推送和部署。

## 本轮确认（2026-11-02）

- 全站中文 / 英文切换，首次进入通过页面内弹窗选择，之后在右上角切换。只持久保存语言偏好，不保存成绩和进度。
- 中文界面除左上角英文 logo、指定署名和必要按键外尽量全中文；英文界面不显示中文。首次语言选择器同时标示两种语言以便辨识。
- 片尾为等量双列：左 ChatGPT、右 Andy Yu，使用大量闲话式条目。按住回车加速，松开恢复；手机提供同等加速按钮，空格仍可跳过。
- 优化现有视觉、动效、深浅主题及手机布局，不改游戏规则；音效仍待制作，不推送、不部署。

- 后续美术修正：蛇头与身体共用身体贴图，独立 SVG 眼睛随方向旋转，不再显示嘴巴或使用独立蛇头 PNG。
- 音效制作改用一对一 MP4 动作参考：13 个片段均标注起点、建议结束和时间码；视频及中间素材放在 Git 忽略的 `production/audio-reference/`，不纳入站点构建。
